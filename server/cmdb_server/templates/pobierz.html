Instalacja agenta

Gotowe polecenia dla nowych maszyn w firmie {{ ctx.tenant_name }}.

Wszystkie polecenia wymagaja tokenu rejestracyjnego tej firmy. Jest jeden na cała organizacje — ten sam wpisuje się na każdej maszynie. Nie możemy go tu wypisać, bo w bazie trzymamy wyłącznie jego skrót; wartość jawna pokazywana jest raz, przy wydaniu. Masz go pod ręka? Wklej zamiast TWOJ_TOKEN. Jeśli nie — wygeneruj nowy.

Linux (Ubuntu, Debian, Raspberry Pi)

{% if paczka_linux %}

Jedno polecenie na maszynie docelowej — nie trzeba niczego klonować ani budować: 

curl -fsSL {{ adres_serwera }}/download/install.sh \
  | sudo bash -s -- --token TWOJ_TOKEN

Skrypt pobiera z tego serwera źródła agenta, sprawdza ich skrót SHA-256, zaklada usługę i timer systemd oraz wysyła pierwszy raport. Agent stoi na samej bibliotece standardowej Pythona, więc działa na każdej architekturze — takze na ARM, gdzie gotowy plik zbudowany na x86 by się nie uruchomil.

Windows

{% if wydanie_windows %}

Wersja obowiązująca w tej firmie: {{ wydanie_windows.version }} ({{ wydanie_windows.arch }}). W PowerShellu jako administrator: 

iwr {{ adres_serwera }}/download/install.ps1 -OutFile install.ps1
.\install.ps1 -Token TWOJ_TOKEN

Skrypt pobiera agenta, sprawdza jego skrót SHA-256, instaluje go w Program Files, zapisuje konfiguracje i zaklada zadanie harmonogramu działające jako SYSTEM.

Skryptu nie da się podac potokiem do iex — PowerShell nie przyjmuje wtedy parametrow, a token trzeba jakoś przekazać. Stąd zapis do pliku.

Przydatne przełączniki

-IntervalHours 4        # co ile godzin raportować (domyślnie 4)
-CaBundle C:\ca.pem     # własne PKI lub certyfikat self-signed
-NoProcessList          # nie zbieraj listy procesow
-NoTray                 # bez ikony w zasobniku
-Silent                 # bez komunikatów, do GPO/Intune
Sam plik agenta jest pod {{ adres_serwera }}/download/agent-windows.exe, ale to nie jest instalator — tego pliku używa mechanizm samoaktualizacji. Uruchomiony wprost wypisze tylko składnię poleceń.
{% else %}
Dla tej firmy nie ustawiono wersji agenta dla Windows, więc instalacja zwróci błąd. Plik dla Windows buduje się na maszynie z Windows (build-agent.ps1) i wgrywa w administracji, w sekcji Wersje agentów — w przeciwieństwie do paczki dla Linuksa nie jest wbudowany w serwer.
{% endif %}

Odinstalowanie agenta

Kto zainstalował agenta jednym poleceniem, musi umieć go usunąć tak samo. Skrypty wydaje ten sam serwer, co instalatory.

Windows

W konsoli PowerShell jako administrator:

irm {{ adres_serwera }}/download/uninstall-agent.ps1 -OutFile uninstall-agent.ps1
.\uninstall-agent.ps1              # zostawia poświadczenie maszyny
.\uninstall-agent.ps1 -RemoveData  # kasuje także poświadczenie

Linux

curl -fsSL {{ adres_serwera }}/download/uninstall-agent.sh | sudo bash
# aby skasować także konfigurację i poświadczenie:
curl -fsSL {{ adres_serwera }}/download/uninstall-agent.sh | sudo bash -s -- --wszystko

Domyślnie zostaje konfiguracja i poświadczenie maszyny — przy ponownej instalacji wraca ona pod tym samym wpisem, bez tokenu i bez drugiego rekordu w ewidencji. Skasowanie ich oznacza rejestrację od nowa.

Odinstalowanie agenta nie usuwa maszyny z panelu — to dwie różne rzeczy. Maszyna zostaje razem z historią raportów; jeśli ma zniknąć z list, wycofaj ją na jej karcie. Odwrotnie też: wycofanie w panelu nie zdejmuje agenta ze sprzętu.

Certyfikat serwera

Jeśli serwer pracuje na certyfikacie wystawionym przez publiczne urzedy (np. Let's Encrypt), powyższe polecenia zadzialaja bez zmian.

Przy certyfikacie self-signed maszyna docelowa nie ma powodu mu ufać i pobieranie się nie powiedzie. Certyfikat trzeba wtedy dostarczyć poza tym kanałem — pobranie go z tego samego serwera, któremu jeszcze nie ufamy, niczego nie dowodzi. Skopiuj plik raz, np. przez scp, i wskaz go przy instalacji: 

curl -fsSL --cacert /ścieżka/ca.pem {{ adres_serwera }}/download/install.sh \
  | sudo bash -s -- --token TWOJ_TOKEN --ca-bundle /ścieżka/ca.pem

Instalator kopiuje certyfikat do /etc/cmdb-agent/ca.pem, więc plik źródłowy można potem usunąć.
